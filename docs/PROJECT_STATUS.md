# Project Status

Updated 2026-09-27.

- **Software status:** Implemented and automated/mock verified; physical game and cable acceptance remains.
- **Controller UI:** Fixed landscape PWA cockpit with a layered physical-device skin: brushed-metal enclosure, leather-style wheel, backlit amber transmission display, mechanical pedals, AT/MT controls and a draggable 6-speed-plus-reverse H-pattern shifter with a real neutral gate. The surface is locked to the live `visualViewport`, blocks browser pinch/double-tap zoom and keeps connection fields at the iOS-safe 16 px focus size. Auxiliary buttons start empty, are added/moved/resized/removed in a drag-and-drop editor and are remembered separately for each game profile. Settings use an internal scrolling overlay; portrait mode shows a rotate prompt.
- **Profiles:** Auto foreground-process detection and persistent Manual override for Generic, Forza Horizon, BeamNG.drive, ETS2, ATS, Assetto Corsa and DiRT/EA WRC.
- **Output:** Exactly one of XInput or vJoy, plus optional foreground-gated keyboard bindings for auxiliary functions. Full direct vJoy coverage requires Device 1 to expose at least 70 buttons; Mock is diagnostics only.
- **Transport:** LAN and USB-tethering interfaces are enumerated with Windows adapter/PnP evidence, including common RNDIS, NCM, ECM, Android and Apple network drivers. Virtual adapters and link-local addresses are not used for QR. A dedicated raw-USB transport is not implemented.
- **Safety:** Pairing, revocable devices, one owner, profile-revision handshake, neutral start, Gateway 120 ms watchdog and independent C# ≤150 ms watchdog.
- **Receiver port:** Fixed dedicated TCP port `32178`. Startup checks the listener owner, releases only a verified stale Wheel Receiver process and refuses destructive takeover from unrelated applications.
- **Protocol:** Exact 8-byte `0x11` state plus exact 8-byte `0x12`/`0x13` staged extensions. Local IPC configuration is never accepted from controller input.
- **Current verification:** 33 JavaScript tests pass, 10 C# tests pass, bridge-pipeline integration passes, full npm audit reports 0 vulnerabilities, and PWA checks at 844×390, 667×375, 640×360, 568×320 and 390×844 have no document overflow or console errors. Mobile Safari and Android Chrome emulation retain `visualViewport.scale=1`, a fixed `(0,0)` page position and 16 px focused connection inputs. QR deep-link auto-pairing, filtered network selection and guarded dedicated-port ownership were exercised. H-pattern drag from neutral to first gear and back to neutral was verified at 667×375, and all major wheel-compatible game profiles expose H mode. Drag/drop, resize and reload persistence were also verified. The Windows Receiver initializes Mock, real ViGEm/XInput and real vJoy backends at neutral.
- **Package:** Electron 44.4.5 / electron-builder 26.15.3 generate `dist-new/LAN Racing Wheel Receiver 1.0.0.exe` as an unsigned portable build using the default Electron icon. The rebuilt package was started with Mock output on dedicated port 32178, served the v27 physical-device PWA and completed QR deep-link pairing at 667×375 without overflow, console errors or automated WCAG A/AA violations.
- **Not yet verified:** Physical iPhone/Android multi-touch, real USB tethering and cable removal, in-game ViGEm/vJoy response, keyboard behavior against elevated games, and per-game mappings/drive modes.
- **Not implemented:** Game telemetry for confirmed RPM/speed/gear/vehicle state and dedicated non-tethering USB.
- **Release decision:** PARTIALLY VERIFIED. Ready for a controlled hardware/game acceptance pass, not an unconditional production claim.
